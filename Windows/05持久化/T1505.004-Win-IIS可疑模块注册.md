# T1505.004-Win-IIS可疑模块注册

> 引入自 SigmaHQ 官方库：`rules/windows/process_creation/proc_creation_win_iis_susp_module_registration.yml`（引入日期 2026-10-27，规则 id 与官方保持一致以便溯源）

## 描述

检测可疑的 **IIS 模块注册**行为，对应 ATT&CK **T1505.004 服务器软件组件：IIS 模块**（T1505 基础技术本地已有覆盖，T1505.004 子技术此前缺失）。

IIS 模块以原生 DLL 形式挂进 w3wp.exe 进程空间，注册完成后**每次对应站点的 HTTP 请求都会自动加载**——攻击者借此实现无需服务重启、不落常规自启动点的 Web 后门持久化（如 FeatureNow、CHOPPER 变种等）。微软 2022 年威胁报告专门披露了东亚地区黑客组织（包括针对国内与港台政府/实体的活动）大规模利用恶意 IIS 扩展驻留服务器的案例，该手法对国内大量 IIS 站点资产针对性极强。

规则检测三种注册路径：
1. `w3wp.exe` 作为父进程执行 `appcmd.exe add module`（最直接的模块注册方式）；
2. PowerShell 命令行含 `system.enterpriseservices.internal.publish`（通过 .NET 企业服务发布 GAC 程序集）；
3. `gacutil /I`（向全局程序集缓存安装程序集，IIS 可从中解析模块）。

规则等级 **high**，官方 falsepositives 为管理行为——IIS 站点部署/更新时确实会正常注册模块，需结合变更窗口与白名单收口。

## 检测日志

- **Windows 安全日志**（国内默认可得）：
  - Event ID 4688：进程创建，需启用「审核进程创建」并开启命令行审计。规则核心字段 `CommandLine`、`Image` 4688 正文覆盖；`ParentImage` 对应 4688 的 `ParentProcessName` 字段（Windows 10 1607 / Server 2016 及以上默认提供），国内主流 Windows Server 2016+ 环境可覆盖。
- **Sysmon 日志**（如已部署）：
  - Event ID 1：进程创建，`ParentImage|endswith '\w3wp.exe'` 直接匹配，无字段缺口。

**⚠️ 国内适配标注（审核重点）**：规则依赖 `ParentImage` 约束父进程为 `w3wp.exe`。Windows Server 2012 R2 及更早版本若未安装补丁或未开启命令行审计，4688 拿不到父进程字段——此时条件无法满足，会**漏报**而非误报。国内存量 IIS 服务器中 2012 R2 占比不低，建议：① 优先在启用完整 4688 审计的主机上落地；② 对老系统可单独用 `appcmd.exe add module` + `gacutil /I` 的命令行关键字做降级监测（放宽父进程约束、接受更高误报）。除此之外规则不依赖 Sysmon 独有字段。

## 检测规则/思路

### Sigma规则

```yaml
title: Suspicious IIS Module Registration
id: 043c4b8b-3a54-4780-9682-081cb6b8185c
status: test
description: Detects a suspicious IIS module registration as described in Microsoft threat report on IIS backdoors
references:
    - https://www.microsoft.com/security/blog/2022/07/26/malicious-iis-extensions-quietly-open-persistent-backdoors-into-servers/
author: Florian Roth (Nextron Systems), Microsoft (idea)
date: 2022-08-04
modified: 2023-01-23
tags:
    - attack.persistence
    - attack.t1505.004
logsource:
    category: process_creation
    product: windows
detection:
    selection_parent:
        ParentImage|endswith: '\w3wp.exe'
    selection_cli_1:
        CommandLine|contains: 'appcmd.exe add module'
    selection_cli_2:
        CommandLine|contains: ' system.enterpriseservices.internal.publish'
        Image|endswith: '\powershell.exe'
    selection_cli_3:
        CommandLine|contains|all:
            - 'gacutil'
            - ' /I'
    condition: selection_parent and 1 of selection_cli_*
falsepositives:
    - Administrative activity
level: high
```

### 建议

- 该规则天然适合与变更管理联动：IIS 正常发布也会触发 `appcmd add module`，建议按运维主机/账户/时间窗加白，**非变更窗口命中即为高置信告警**。
- 命中后重点排查：注册的模块 DLL 路径与签名状态（恶意模块多为无签名、放在 `C:\Windows\Temp` 或站点可写目录）、`appcmd list modules` 比对基线、模块对应的站点是否有异常 POST 流量。
- 配套检测：模块 DLL 落盘（Sysmon Event ID 11 file_event，模块写入 `%windir%\Microsoft.NET\...` 或站点目录）、gacutil 向 GAC 安装非微软签名程序集（文件签名维度需 Sysmon，故本条仅作思路）。
- 国内语境：微软报告披露的 IIS 后门家族（如 FeatureNow、绕过 CASI/NetSPI 类）常配合 `appcmd` 静默注册，若环境中已有 IIS 资产清单，可将本规则命中与资产归属（对公/对内）联动分级。
