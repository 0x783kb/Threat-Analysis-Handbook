# T1003.001-Win-Dumpert进程内存转储工具执行

> 引入自 SigmaHQ 官方库：`rules/windows/process_creation/proc_creation_win_hktl_dumpert.yml`（引入日期 2026-10-23，规则 id 与官方保持一致以便溯源）

## 描述

攻击者使用 **Dumpert**（Outflank 开源工具）转储 `lsass.exe` 进程内存，直接获取明文外的凭据材料（MITRE ATT&CK T1003.001）。Dumpert 通过直接系统调用（Direct Syscalls）+ API unhooking 方式调用 `ntdll` 的内存转储能力，可绕过大多数 EDR 的用户态 Hook，生成包含 LSASS 内存的 minidump 文件，供离线提取凭据。

官方规则通过进程创建事件的命令行特征（`Dumpert.dll` / `Dumpert.exe`）及 Dumpert 二进制的 Imphash 进行匹配，等级 **critical**。

## 检测日志

- **Windows 安全日志**（国内默认可得）：
  - Event ID 4688：进程创建，记录 `rundll32.exe` 加载 `Dumpert.dll` 或直接执行 `Dumpert.exe` 的命令行（需启用「审核进程创建」并在进程创建事件中加入命令行）。
- **Sysmon 日志**（如已部署，匹配更全）：
  - Event ID 1：进程创建，额外提供 `Hashes`（Imphash）与 `ParentImage` 字段。

**说明**：规则中 `Hashes|contains: 'IMPHASH=09D278F9...'` 分支依赖 Sysmon Event ID 1 的 `Hashes` 字段，4688 环境下该分支不触发；但 `CommandLine|contains: 'Dumpert.dll'/'Dumpert.exe'` 为独立 OR 分支，仅靠 4688 命令行审计即可命中。

## 检测规则/思路

### Sigma规则

```yaml
title: HackTool - Dumpert Process Dumper Execution
id: 2704ab9e-afe2-4854-a3b1-0c0706d03578
status: test
description: Detects the use of Dumpert process dumper, which dumps the lsass.exe process memory
references:
    - https://github.com/outflanknl/Dumpert
    - https://unit42.paloaltonetworks.com/actors-still-exploiting-sharepoint-vulnerability/
author: Florian Roth (Nextron Systems)
date: 2020-02-04
modified: 2026-09-16
tags:
    - attack.credential-access
    - attack.t1003.001
logsource:
    category: process_creation
    product: windows
detection:
    selection:
        - Hashes|contains: 'IMPHASH=09D278F9DE118EF09163C6140255C690'
        - CommandLine|contains:
              - 'Dumpert.dll'
              - 'Dumpert.exe'
    condition: selection
falsepositives:
    - Very unlikely
level: critical
```

### 建议

- 该规则 logsource 已是抽象 `category: process_creation`，可直接映射到 4688 命令行审计，无需 Sysmon。
- 若内网仅开启 4688 未采集命令行，此规则不可用，需先按《本地Sigma规则优化报告》中的 L2 门槛开启命令行记录。
- 命中后立即隔离主机并排查 `OUTFLANK-...`、`Dumpert` 相关 dump 文件落地（通常为 `C:\Windows\Temp\dumpert.dmp`）。
